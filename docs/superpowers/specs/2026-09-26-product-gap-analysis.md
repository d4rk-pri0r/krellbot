# Krellbot product gap — inspected engine and site

The local engine remains the free product; official JSON packs are optional. This is the smallest vertical path from the current repositories to a truthful first-run. **A/B are implementation work in isolated engine/site branches, not a published three-platform release.** The newer product brief's slices C–G follow A/B; no paid or live-trading success is inferred from a wizard visit.

| Slice | Current source | Target and smallest credible next change |
|---|---|---|
| **A — install/server** | `src/krellbot/ui/server.py` already provides loopback-only token, session, CSRF, Host/Origin checks and paper-only actions. `ui --open` and PyInstaller one-dir archive/CI exist on the engine branch; site worktree now validates a pinned release manifest and verifies checksums before staged install/rollback. Only macOS arm64 frozen smoke has run locally. | Verify native Windows/Linux CI, release URL/manifest and clean-machine install, PATH, keyring, browser launch; sign/notarize when credentials exist. Do **not** publish a one-liner for an unbuilt OS or represent checksum as publisher signature. |
| **B — wizard/trust** | Static dashboard is functional but is not a first-run flow. `doctor` now distinguishes install/trading readiness. | Add visit-only preference, local metadata-only trust snapshot, gated welcome/security/next routes, then polished responsive shell. A visit never means key connected or pack armed. Retain existing POST/live refusal tests. |
| **C — keys** | `cli.py`/`cli_keys.py`, `secrets.py`, and Kraken/Coinbase venue `check_key()` support keychain storage and trade/withdraw probes; the UI has no key-entry flow. | Extract a shared add/probe operation, reject withdraw-enabled or unverifiable live credentials, and add token/CSRF-protected UI form with immediate keychain write, masked status, revoke, and no durable browser secret. Never claim a permission check succeeded if unavailable. |
| **D — packs/paper arm** | JSON DSL loader/linter, `cmd_setup`, Ed25519 license cache, CLI paper arm/tick and local dashboard paper actions exist. There is no in-UI activation/redeem, pack picker, verified signed stats bundle, or in-app service installation. | Reuse shared CLI operations in guarded UI routes: redeem activation key, verify/download packs, choose an installed valid pack, paper-arm and install OS schedule; keep custom packs free and Stripe checkout on krellbot.dev. Do not invent performance numbers. |
| **E — command center** | Disk-backed armed-pack, journal, receipts, disarm/stop-all/adopt views exist in the small dashboard. | Improve hierarchy, explicit as-of/window/unit/empty/error states and doctor/scheduler status without altering stop ownership or live-arm refusal. |
| **F — Advanced** | Pack DSL whitelist, lint and backtest receipts exist; custom editing is JSON/CLI. | Visual schema-constrained editor emitting only valid `schema_version: 1` JSON; receipt view with window, fees/slippage and drawdown. |
| **G — live** | `cli.py` currently builds Kraken/Coinbase adapters for live ticks behind `KRELLBOT_ENABLE_LIVE=1` and checks `can_trade`/`can_withdraw`; the UI refuses live arm. This is code wiring, **not** proof of a real trade or safe release. | Test actual adapter/order semantics in controlled sandbox with stop monotonicity, pack-owned sell cap and no `CancelAllOrdersAfter`; retain typed LIVE CLI gate until demonstrated. |

**First-run cut:** verified per-OS artifact → gated local UI → honest welcome/trust → existing paper dashboard. That is A/B, not the full purchase-to-armed mission. C/D are the next vertical dependencies; signed artifacts, native CI, and a live configured endpoint gate any public install claim.
