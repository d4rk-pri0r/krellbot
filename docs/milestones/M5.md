# M5: signed Strategy Pack catalogue (free + paid)

**Exit:** user browses a signed catalogue and one-click installs free/paid packs in-app; activation redeem has a frontend caller; pack library lifecycle gaps (rollback route vs client) are coherent. `PAPER_ONLY_RELEASE` stays `True`.

**Why this order:** Signing/verify already exist (`license.py`, `license_activation.py`) but store UX is stubbed (gap map stage 4). Depends on a reachable UI (M2) more than on keys; can parallel M4 after M2.

Rules for every task are in `AGENTS.md`. Agents skip `[owner]` tasks. Agents pick the lowest-numbered unchecked engineering task that has no open PR and does not depend on an unmerged task.

**Parallelism:** M5.1 first (risk-path); M5.2–M5.3 after M5.1; M5.4–M5.5 after M5.2.
