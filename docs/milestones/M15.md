# M15: built-in trading modes as packs (DCA / grid / rebalance)

**Exit:** DCA, grid, and rebalance exist as **first-class built-in packs** (or pack-mode presets) that validate, open in Studio with readable graphs, and run pinned-data Research without inventing live performance; Workstation can paper-arm at least one mode end-to-end behind fakes. Unfinished M0–M13 owner gates stay in those files — reference only. Agents keep `PAPER_ONLY_RELEASE` True. Do not invent a Learn view. Do not flip `PAPER_ONLY_RELEASE`. Do not place real orders.

**Why this order:** Octobot “tentacle mode” gap: competitors ship named trading modes; Krellbot’s spine is author → research → paper. M5 catalogue + M6 Studio/authoring + M4 Research charts exist. Next is **modes as packs** so modes reuse validate-before-arm, receipts, and paper — not a parallel engine.

Rules for every task are in `AGENTS.md`. Agents skip `[owner]` tasks. Agents pick the lowest-numbered unchecked engineering task that has no open PR and does not depend on an unmerged task.

**Parallelism:** M15.1 first (mode contract); M15.2 ∥ M15.3 ∥ M15.4 after M15.1; M15.5 after all three packs; M15.6 after M15.5; M15.7 after M15.2 (paper one mode). Prefer expressing modes inside existing DSL; bounded schema extensions only when a mode cannot be honest otherwise — never generative AI choosing orders.
